## A6.0 — Two defects in your OWN harness, fix them first (they cost the orchestrator a verification round)
Both are in `.dispatch/A3-live.mjs` and both produced false results when it was re-run:
1. **Count-based assertions are not idempotent.** `feed has both posts` and `search finds the need` assert on the TOTAL number of rows in the shared tables, so a second run against the same database fails on the fixtures the first run left behind (observed: `feed has both posts — 6 entries`). Assert on the ids THIS run created — the feed must CONTAIN them, not equal a count.
2. **The DB-side assertions ignore the server's configured database.** `sql()` runs `psql` against a hardcoded connection (`komun_a`), so when the server is pointed at another database every DB claim silently queries the wrong one (observed: `matches.message is NULL` FAILED on a fresh DB purely because the id it names does not exist there — the value is genuinely NULL, the query just looked in the wrong place). Derive the connection from the same source the server uses, or pass it in.
Fix both, then re-run and report the numbers. A harness that cannot be re-run is worth less than its output.
