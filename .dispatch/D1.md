## ADDENDUM (orchestrator, 2026-09-24) — behaviours the docs must state, verified at runtime

Everything below was observed against a live server during M1–M3 verification; none of it is inferable from
reading the code alone, and each is a fact a deployer or client author needs.

1. **The posts list is paginated.** `limit` defaults to **100** and caps at **200**; `offset` is supported.
   A client that assumes an unbounded feed silently loses rows on a busy server.
2. **Currency precedence for a listing or a want**: the offer's own `currency`, else the post's, else
   `[market] default_currency`; with none of the three it is a 400 naming the missing currency. An offer MAY
   name a currency different from the post's, and that currency then governs the deal. An `accept` must
   restate `amount_cents`.
3. **`[market] default_currency` is unset by default.** A malformed value (e.g. `"cad"`) refuses to start and
   the message names the key, the value and the remedy.
4. **Reviews** are writable only against a `completed` deal, one per participant per deal, and immutable
   (the UNIQUE `(match_id, reviewer_id)` surfaces as a 409, never a 500). `rating` is a whole number 1..5.
   `GET /api/users/{id}` returns `rating_avg` (mean to one decimal, `null` when there are none) and
   `rating_count`, computed from `deal_reviews` — there is no denormalised counter column.
5. **Category admin audit rows** carry `subject_id = NULL` with the category slug in `detail`, because
   `audit_events.subject_id` is a UUID and `categories` is keyed by slug (and 001 is frozen).
6. **Endpoint inventory to document** (all under `/api`): `GET /categories?scope=aid|market|both`;
   `POST /admin/categories`, `PATCH /admin/categories/{slug}` (admin or superadmin, audited);
   `POST /conversations/{id}/offers` and `GET /conversations/{id}/offers` (participant-only);
   `POST /matches/{id}/reviews`, `GET /users/{id}/reviews`. Completing a deal is `PATCH
   /conversations/{id}/status` with `{"status":"completed"}` from `accepted`, and it marks a listing
   `fulfilled` with `sold_at` + `buyer_id`; a listing that is already sold refuses a second completion (409).
7. **`deploy/seed.sql`**: verify the 23 categories (15 market-only, 6 both, 2 aid-only) by RUNNING it
   against a fresh database, and state the counts you observed.
