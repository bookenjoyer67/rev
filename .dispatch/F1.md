Task:
1. **F1.1 `categories.ts`** — one module that fetches `GET /api/categories?scope=market` once and derives the
   label/slug list the market UI needs, with the `both` rows included. No hardcoded category list anywhere:
   the seeded table is the source of truth (15 market-only + 6 both = 21 rows for `scope=market`).
2. **F1.2 `MarketCard.svelte`** — one listing or wanted ad: title, price rendered from `price_cents` +
   `currency` (an absent price shows "Free / negotiable" rather than "$0.00"), category label, condition,
   location name, and a link to `/p/{id}`. `kind` must be visible (`listing` vs `want`) — a wanted ad is not
   a listing and the card must not look like one.
3. **F1.3 `/market`** — the browse page: kind toggle (listing | want | both), category filter fed by F1.1,
   price range, condition, and a search box, all reflected in the URL query string so a filtered view is
   linkable, plus the results via `GET /api/posts` with those filters. Empty state, loading state, and an
   error state that shows the server's message (a bad filter must not look like "no results").
   **The posts list is paginated server-side** (`limit` defaults to 100 and caps at 200, with `offset`):
   pass an explicit `limit` when a view genuinely needs more than the default, and never assume the list
   you get back is unbounded — a busy server's feed will be truncated at 100 otherwise.
4. **F1.4 `/market/new`** — post a listing or a wanted ad: kind, title, body, category (market scopes only),
   price + currency (currency optional — when it is empty the server applies its own precedence, and you
   must NOT invent a default in the client), negotiable toggle, condition select, and a location via
   LocationMap's pick mode. `item_condition` values must match the `chk_posts_item_condition` CHECK list in
   `migrations/001_schema.sql` exactly — quote that list in a comment and read it from the file, do not guess.
   On success go to the new post's `/p/{id}`.
5. **F1.5 Tests** in `web/src/tests/market.test.ts`: price formatting (including the no-price case), the
   kind distinction, the category list derivation (a `both` row appears for `scope=market`), and the
   query-string round trip (filters in → same filters out). Vitest currently passes 52 tests in 5 files;
   keep all of them passing and add these.
