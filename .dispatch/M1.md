1. **M1.1 `[market]` config.** Add a `MarketConfig` with `default_currency: Option<String>` (ISO-4217,
   **unset by default** — no invented value). Validate the shape at load (3 uppercase letters) and refuse
   to start with a clear message naming the key and the bad value. `currency` on a listing always wins;
   the config value is only the fallback when a market post arrives without one.
2. **M1.2 Categories API.** `GET /api/categories?scope=aid|market|both` — public, no session, returns the
   active rows ordered by `sort_order, label`, each with `slug, label, scope`. `scope` filters to rows whose
   scope equals it OR is `'both'` (so the market UI asks for `scope=market` and gets all 21 market-usable
   rows, the aid UI gets 8). An unknown scope is a 400 listing the accepted values. Inactive rows never
   appear to non-admins.
3. **M1.3 Admin category editing** (plan decision B8: "admin-editable at runtime"). `POST /api/admin/categories`
   and `PATCH /api/admin/categories/{slug}` for role admin/superadmin only: create, relabel, reorder,
   flip `active`. Slugs are lowercase-kebab and immutable after creation. Write an `audit_events` row for
   every change (actor, action, subject, detail), the same way the existing role change does.
4. **M1.4 Market filters on the posts API.** Extend the existing list endpoint so a market view can ask for
   what it needs: `kind` (listing|want), `category`, `min_price_cents`, `max_price_cents`, `currency`,
   `item_condition`, plus the existing search/limit/offset. A filter whose value is malformed (a non-ISO
   currency, a non-numeric price, an unknown condition) is a 400 naming the parameter — never a silent
   empty list. Market fields come back in the post payload for market kinds and are absent/null otherwise.
5. **M1.5 Tests** in `crates/server/src/tests/market.rs`: the config validator (accepts `USD`, rejects
   `usd`, `US`, `USDD`, empty), the `scope=market` union semantics (includes `both`, excludes `aid`), the
   unknown-scope 400, the admin-only enforcement (a plain user gets 403), the audit row, and each market
   filter's happy path + its 400.
