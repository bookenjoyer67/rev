## ADDENDUM (orchestrator, 2026-09-24) — three P2s found while verifying M2

All three live in files you already own (`crates/server/src/api/conversations.rs`,
`crates/server/src/db/conversations.rs`, `tests/market.rs`). Each fix needs a test beside it; do not change
the negotiation semantics otherwise.

1. **`GET /api/conversations/{match_id}` returns 500 to a non-participant.** Observed at runtime: an
   outsider got `500` with body `{"error":"conversation not found"}`, while `GET .../offers` gives that same
   user a correct `403`. Make the thread read refuse a non-participant with **403**, consistent with the
   offers endpoints.
2. **A withdrawn or completed thread still accepts new offer rows.** After a `decline` had withdrawn a
   thread, appending another `offer` was accepted. A thread that is not `proposed` or `accepted` must
   refuse new offers with **409 naming the current status**, the way the status transitions already do.
   Existing rows are never touched.
3. **A second deal can complete on an already-sold listing and overwrite the sale.** Two matches on one
   listing can each be accepted and completed; the second completion rewrites `posts.sold_at` and
   `posts.buyer_id`. A completion whose listing already has `sold_at` set must be **409** ("this listing is
   already sold").
