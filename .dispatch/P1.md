## The problem, observed at runtime during M1 verification

`POST /api/admin/categories` with a body whose `scope` is not a real scope answers **422 with axum's own
serde text**:

    Failed to deserialize the JSON body into the target type: scope: unknown variant `nope`,
    expected one of `aid`, `market`, `both` at line 1 column …

`GET /api/categories?scope=nope` already answers a **400 that names the accepted values**, and every other
market route parses its inputs by hand for exactly this reason. Make the body case match the query case.

## Task

   so an unknown value is a **400 whose message names the accepted values** (`aid`, `market`, `both`) — use
   the GET's wording if it fits, otherwise keep both messages saying the same thing in the same style.
2. A missing or malformed JSON body must still be a 400, never a panic and never a 500.
3. Change nothing else: no other status code, message, route, or behaviour. `PATCH
   /api/admin/categories/{slug}` keeps whatever it does today unless it has the identical defect, in which
   case fix it the same way and say so.
4. Add the test: a create whose `scope` is unknown answers 400 and the body names the accepted values, and a
   valid create in the same test still answers 201.
