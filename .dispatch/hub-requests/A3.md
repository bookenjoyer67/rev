# Hub request — A3 (Agent A): five backend files outside my write set

A3 removes the community concept from `crates/server/src/api/**` and `crates/server/src/db/**`.
Five files outside that set still read or write the dropped tables and columns. I have not
touched any of them. Every diff below is exact against the tree as of this card.

**Why this is not optional polish.** Two of the three A3 greps cannot reach their stated result
without these edits, and three of the five files contain statements that fail at runtime today
because the table or column they name is not in the squashed schema:

| file | what breaks | grep hits it owns |
|---|---|---|
| `crates/server/src/repl.rs` | `SELECT … FROM communities` × 3 — every REPL banner, `stats` and `list-communities` | `communit` ×10, `slug` ×3 |
| `crates/server/src/tasks/registration.rs` | `SELECT … FROM communities` × 2 — the hourly directory registration | `communit` ×6, `slug` ×3 |

### A concern about `discovery.registration_mode`, which I implemented as instructed

Hub item 6 said the new `[registration] mode` supersedes `discovery.registration_mode`, and this
card told me to make `api/directory.rs` read the registration mode from the live config. I did:
`api/directory.rs` now gates `POST /api/directory/register` on `config.registration.mode ==
"open"`.

They are not the same setting. `discovery.registration_mode` gated **which servers may list
themselves in this server's directory**. `registration.mode` gates **whether a person may create
a user account here**. Collapsing them means an operator who runs an open public directory but
wants invite-only user accounts — a completely ordinary combination, and arguably the default for
a directory server — silently finds directory registration behind `require_auth`, because they
set `[registration] mode = "invite"` for an unrelated reason.

Nothing in A3 breaks because of it and the code is simpler, so I have not fought the instruction.
If you want the two separated again later, the clean shape is a `discovery.open_registration:
bool` — the string was only ever compared against `"open"`, so it never needed three values.
