## 1. `web/src/lib/components/../stores/server.ts` → `web/src/lib/stores/server.ts`

1. `NodeInfo.communities_count` and `NodeInfo.federation_enabled` are not emitted by the backend.

2. `parseSlug` and `resolveSlug` exist only to resolve `slug@domain` into a community on a remote
   server. A6.1 deletes every caller (`web/src/routes/c/**`). After that they are unreachable.

   deliberately — it is a generic server lookup, not community machinery. Say the word if you
   would rather it went too.

## 3. `web/tsconfig.json` — the last surviving `npm run check` warning

After A6's deletions land, `npm run check` is **0 errors / 1 warning**, and the one warning is
not in any source file:

```
WARNING "tsconfig.json" 1:1 "Cannot find type definition file for 'node'.
  The file is in the program because:
    Entry point of type library 'node' specified in compilerOptions"
```

`.svelte-kit/tsconfig.json` (generated by `svelte-kit sync`, so not editable) sets
`"types": ["node"]`, and `node_modules/@types/` contains only `aria-query, chai, cookie,
deep-eql, estree, trusted-types` — `@types/node` was never installed. The proper fix is
`npm i -D @types/node`, which I cannot run (no egress in this container, and STANDING RULE 2
forbids it regardless). The override below is the fix that needs no network:

## Note, not a request: the location picker in `web/src/routes/aid/new/+page.svelte`

I deleted the piggpin `<iframe>` map picker from that page (it is mine to edit). It keyed off
`community.map_community_id`, `community.map_secret_hex` and `nodeInfo.relay_url`;
`grep -rn "relay_url\|map_community\|map_secret" /workspace/crates/server/src` returns **nothing**,
so no handler has ever emitted any of the three and the picker could not activate. Removing it
removed dead code, not a feature.

The consequence is real though: `location_lat`/`location_lon` are still sent on create, but
nothing in the UI sets them any more, so new posts carry no coordinates and will not appear as
pins on B2's `/map`. Replacing the picker means a click-to-place mode on B2's `LocationMap`
(which today takes `lat`/`lon`/`markers` and emits nothing) or a call to `/api/geocode` against
the typed location name — `/api/geocode` proxies Nominatim, which this container cannot reach, so
I could not have verified that path here. Either way it is B2's component and B's card.
