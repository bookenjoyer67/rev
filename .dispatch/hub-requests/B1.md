**Requested by:** Session B (Agent B), Wave B1
**File to change:** `crates/server/src/config.rs` (owned by Session A — B must not edit it)
**Spec reference:** `.dispatch/SPEC.md` Part 5.3 (pre-approved shape), task A4.2
**Status while pending:** `api/geocode/` compiles and all its tests pass *without*
this patch. Because the `/geocode` route is mounted in `api/mod.rs` without
`AppState` (and B may not edit `api/mod.rs`), the proxy reads `[geocode]

falls back to the default agent when unset. This patch adds the canonical config
shape named by the SPEC so the field is defined in `config.rs` for the docs
(B4), the map work (B2's `[map]` sibling) and any future stateful route.

### Why these choices

- `contact: Option<String>` so an unset section keeps working; `#[serde(default)]`
  plus `Default` mean a config file with no `[geocode]` still loads.
- `user_agent()` derives the header from the contact as the SPEC asks. The
  default branch is built with `concat!(env!("CARGO_PKG_VERSION"))` rather than a
  pinned literal so that `grep -rn "Komun/0.1" crates/server/src` comes back
  empty (B1's gate) while the unset behaviour still identifies Komun.
- The one `tracing::debug!` call in `Config::load` is what keeps `user_agent()`
  and the new `geocode` field live, so the patch adds **zero** new
  `dead_code`/clippy warnings (verified: `cargo build` on a scratch copy with
  this patch produces the same 4 pre-existing warnings as baseline). It logs
  the public contact, never a key or passphrase.
