# Hub requests — Card B2 (OSM map: Leaflet component + `/map`)

**Requested by:** Agent B (Session B), Wave B2
**Files B2 may not edit:** `web/svelte.config.js` (no owner listed in the session contract) and
`crates/server/src/config.rs` (Session A). B2 owns only `LocationMap.svelte`,

Two independent items:

### Why

`LocationMap.svelte` uses Leaflet, which loads raster tiles as `<img>` elements from
`https://tile.openstreetmap.org/{z}/{x}/{y}.png`. The frozen CSP sets
`img-src 'self' data: blob:`, so those requests are refused — verified against the built page:

```
$ grep -o "img-src[^;]*" web/build/index.html
img-src 'self' data: blob:
```

Leaflet's attribution control still renders, but no tile can load. The default `tile_url` is
operator-configurable (item 2), and a runtime-variable CSP is not something a static build can express,
so this adds the default OSM host; operators pointing `tile_url` at their own server must add that host
here too. It does not weaken anything else in the directive.

### Why

SPEC Part 5.3 lists a `[map]` block as a pre-approved shape and card B2 offers it as an optional hub
request. The values mirror exactly what `LocationMap.svelte` defaults to, so defining the section and
later feeding it through `/api/node` changes no current behaviour. The `tracing::debug!` line (same
pattern as B1's `[geocode]` log) is what keeps `MapConfig` and both of its fields live, so the patch
adds **zero** new `dead_code`/clippy warnings.

`/map` does not read this section in B2 — `/api/node` exposes nothing about tiles yet, and the card
says "the defaults are the contract for this card". This only records the shape.
