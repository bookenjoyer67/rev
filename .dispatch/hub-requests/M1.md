# Hub request M1 — add a commented `[market]` block to `config.example.toml`

**Requested by:** Session A (Agent A), Card M1 — Market foundation
**File to change:** `config.example.toml` (owned by Session B — A must not edit it)
**Spec reference:** `.dispatch/SPEC.md` Part 1.3 decision **B7** ("Per-listing ISO-4217 +
optional server-level `[market] default_currency`, unset by default"), task M1.1

**Status while pending:** nothing is blocked. `crates/server/src/config.rs` already defines
`MarketConfig` with `#[serde(default)]`, so a config file with no `[market]` section parses and
the key stays `None` — which is the shipped behaviour B7 asks for. This patch is documentation:
without it an operator has no way to discover the key exists, and the only two outcomes of that
are a node that never sets a currency or one that learns the key's name from the source.

**Why the line stays commented out:** an example file is copied verbatim far more often than it is
read, so an uncommented `default_currency = "USD"` would not document a default — it would create
one, in a currency chosen by whoever wrote the example rather than by the operator. Unset is the
shipped default and the example has to show it as unset.

```diff
+# Fallback currency for marketplace listings that arrive without one of their
+# own, as an ISO-4217 alphabetic code: exactly three uppercase letters. A
+# listing's own currency always wins; this is consulted only when it has none,
+# and when both are absent the listing simply carries no currency.
+# Unset by default, and left commented out deliberately — there is no currency
+# that is right for a server that has not chosen one, and a value here would
+# price every listing on this node in a unit nobody picked. A malformed value
+# is a startup failure naming this key, not a surprise on the first listing.
+# default_currency = "USD"
```

## Note for the orchestrator

M1's gate proves the key is actually read rather than merely documented: the config test
`tests::market::market_config_tests::a_well_formed_default_currency_is_accepted` parses
`[market]\ndefault_currency = "USD"` through the real `Config` and asserts the value arrives, and
`a_malformed_default_currency_refuses_to_start_and_names_the_key_and_the_value` asserts the
startup refusal — so the block above cannot be a comment describing a key that nothing consumes.
